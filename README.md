# Televote

Сервис анонимного голосования под пик ТВ-эфира: минутный ролик, 100 млн
зрителей, QR-код на экране. Голосование без регистрации, с дедупликацией.

Тестовое задание. Обоснование архитектуры — [`ARCHITECTURE.md`](ARCHITECTURE.md),
подробный дизайн — [`docs/design.md`](docs/design.md), артефакты работы с ИИ —
[`docs/ai/`](docs/ai/).

## Запуск

```bash
make demo
```

Одна команда: собирает образы, поднимает стенд, дожидается готовности, создаёт
демо-опрос и печатает ссылки.

```
  Голосование   http://localhost:8080/p/demo
  QR-код        http://localhost:8080/p/demo/qr.png
  Админка       http://localhost:8080/admin      admin / dev-only-change-me
  Grafana       http://localhost:3000
```

**Нужно:** Docker с 6 ГБ памяти и свободные порты 8080–8082, 3000, 55432.
Порт занят — переопредели переменной: `APP_PORT=9090 make demo`.
Первый запуск занимает 2–4 минуты, дальше около минуты.

Остановить и стереть данные: `make down`.

## Что проверить

**`make smoke`** — семь шагов end-to-end. Главный: один голосующий на **двух
разных инстансах** даёт **ровно один** голос.

**`make load`** — стоимость приёма одного голоса и сверка: сумма счётчиков
после дренажа равна числу принятых голосов.

**`make chaos`** — отказ Redis, ребаланс консьюмеров, падение Postgres.
Каждый сценарий заканчивается сверкой агрегата, а не проверкой «сервис отвечает».

**`make test`** — unit-тесты с детектором гонок.
**`make test-integration`** — на настоящих Postgres и Redis через testcontainers.
**`make lint`** — golangci-lint, включая запрет импортов через границы слоёв.

Результаты последнего прогона — [`docs/load-report.md`](docs/load-report.md).

### Руками

```bash
# проголосовать
curl -X POST localhost:8080/api/v1/polls/demo/vote \
  -H 'Content-Type: application/json' \
  -d '{"choices":[1],"voter":"проверка-1"}'
# → 202 {"status":"accepted"}

# результаты (подсчёт асинхронный, подожди пару секунд)
TOKEN=$(curl -s -X POST localhost:8080/api/v1/admin/login \
  -H 'Content-Type: application/json' \
  -d '{"login":"admin","password":"dev-only-change-me"}' | jq -r .token)
curl -s localhost:8080/api/v1/admin/polls/demo/results -H "Authorization: Bearer $TOKEN" | jq
```

`202`, а не `200`: голос принят к обработке, посчитает его консьюмер. Отвечать
«посчитан» за то, что ещё лежит в очереди, — значит врать клиенту.

## Как это работает

```
зритель → CDN ─┬─ страница и конфиг опроса (кэшируются)
               └─ POST /vote → LB → vote-api (stateless)
                                       │ produce
                                  ┌────▼─────┐
                                  │  Kafka   │  партиции по voterID
                                  └──┬────┬──┘
                    counting-consumer │    │ fraud-consumer
                            EVALSHA ──▼    └──► агрегаты по подсетям
                             Redis Cluster
                                  │ снапшот → финализация
                             Postgres → админка
```

**В окне эфира жёстко требуется только принять голос.** ТЗ не задаёт времени
получения результата, и это определило форму системы: дедуп и подсчёт делает
консьюмер на дренаже, а отказ Redis становится задержкой результата вместо
потерянного эфира.

Голос применяется одним атомарным Lua-скриптом: дедуп и инкремент вместе.
Дедуп-ключ служит ключом идемпотентности — Kafka доставляет at-least-once, и
без этого свойства каждый ребаланс группы завышал бы результат.

## Структура

```
cmd/televote        точка входа: main.go — жизненный цикл, wiring.go — зависимости
cmd/migrate         миграции Postgres со встроенными SQL-файлами

internal/           бизнес-логика: знает про голосование
  domain            опрос, правила выбора, FSM статусов, агрегат, расчёт ёмкости
  vote              Lua-скрипт, вывод voterID, шардирование ключей
  producer          отправка голоса в Kafka
  consumer          подсчёт и анализ накрутки, две независимые группы
  snapshot          Redis → Postgres, расписание, финализация
  pollcfg           кэш конфигов опросов в памяти процесса
  capacity          советчик ёмкости для KEDA
  httpapi           приём голоса, админка, страницы
  auth              argon2id, JWT, роли
  storage/postgres  репозитории control plane
  config            конфигурация с проверкой инвариантов при старте

pkg/                механизмы: ничего не знают про голосование
  health            готовность и живость
  httpx             клиентский IP, лимит частоты, ASN-фильтр, заголовки

deploy              docker-compose, конфиги Redis и nginx
scripts             smoke и chaos-сценарии
load/k6             нагрузочный профиль
docs                дизайн с требованиями, отчёт нагрузки, артефакты ИИ
```

`internal/domain` не импортирует ничего из проекта — это проверяет `depguard`,
а не соглашение.

## Особенности, которые стоит знать

**Дедупликация** держится на случайном идентификаторе в `localStorage`, который
сервер хэширует солью опроса. Останавливает F5, закрытие вкладки и двойной клик.
Не останавливает инкогнито, другой браузер и скрипт — ТЗ просит защиту «на
уровне обычных пользователей» и явно не требует антифрода.

**Приватность** — свойство конструкции: дедуп-ключ хранит факт голосования, но
не выбор, а отдельные голоса в Postgres не попадают вовсе. Где гарантия всё же
протекает, честно перечислено в [`docs/design.md`](docs/design.md) §12.

**Результаты появляются не мгновенно.** Это осознанное решение, а не
ограничение: см. `ARCHITECTURE.md`.
