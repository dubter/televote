# Требования

Выведены из текста ТЗ. Каждое требование помечено источником:
**явно** — сказано в ТЗ; **выводимое** — следует из сказанного; **наше** — решение команды.

---

## 1. Четыре наблюдения из ТЗ, определившие дизайн

**«Обезличенные результаты» — требование к модели хранения, не к UI.**
Связь «голос ↔ человек» не должна существовать в принципе. Отсюда: дедуп-ключ хранит
факт голосования, но не выбор; восстановить, кто за что проголосовал, невозможно
по конструкции.

**«Не слишком защищённая от обхода» — требование НЕ делать.**
Редкий случай, когда ТЗ ограничивает сверху. Proof-of-work, fingerprinting,
поведенческий антифрод, привязка к телефону — вне скоупа. Это экономит работу и
защищает от переусложнения.

**«Чтоб не накручивали» задаёт асимметрию ошибок.**
Про потерю голосов ТЗ не говорит ничего, про накрутку — говорит. Значит потерять
доли процента допустимо, посчитать лишние — нет. Отсюда идемпотентность операции
голоса и отказ от at-least-once доставки дельт.

**«1 вопрос любого типа: multiple choice, a/b, …» — многоточие требует решения.**
В агрегатную модель ложатся: выбор одного, выбор нескольких, шкала и рейтинг
(это выбор одного над упорядоченными опциями), да/нет (выбор одного из двух).
Не ложится свободный текст: нет агрегата, нет обезличивания, нет дедупа по
содержанию. Вне скоупа, обоснованно.

## 2. Функциональные требования

| ID | Требование | Источник |
|---|---|---|
| **FR-1** | Создать опрос: один вопрос, N вариантов, тип `single` или `multiple` | явно |
| FR-1.1 | `single` покрывает A/B, да/нет, шкалу | выводимое |
| FR-1.2 | `multiple` с ограничениями `min_choices`/`max_choices` | выводимое |
| **FR-2** | Опрос доступен по короткой ссылке и QR-коду | явно |
| **FR-3** | Проголосовать анонимно, без регистрации | явно |
| **FR-4** | Дедупликация уровня «обычный пользователь»: F5, повторное открытие, двойной клик | явно |
| **FR-5** | Посмотреть обезличенные результаты в админке | явно |
| FR-5.1 | Результаты доступны во время эфира и после закрытия | выводимое |
| **FR-6** | Управление окном голосования: открыть, закрыть, расписание | выводимое (окно голосования подразумевает управление) |
| **FR-7** | Аутентификация админки | выводимое («на нашей стороне» = не публичный доступ) |
| **FR-8** | Голоса вне окна голосования отвергаются | выводимое (иначе накрутка после эфира) |

### Уточнения к FR-4

Дедупликация останавливает: повторный клик, обновление страницы, повторное открытие
ссылки. Не останавливает: режим инкогнито, другой браузер, скрипт. **Это соответствует
ТЗ, а не является недоработкой.**

### Уточнения к FR-5

«Обезличенные» означает: только агрегат (голосов на вариант, бюллетеней всего,
проценты). Индивидуальные голоса не хранятся и не отдаются никому, включая админа.

## 3. Нефункциональные требования

| ID | Требование | Значение | Источник |
|---|---|---|---|
| **NFR-1** | Пиковая нагрузка | 100 млн зрителей, окно 60 с | явно |
| NFR-1.1 | Расчётная конверсия | 30 % → 30 млн голосов, ~2M RPS | **наше допущение**, см. A-1 |
| **NFR-2** | Доступность в окне эфира | второго шанса нет: отказ = потерянный эфир | выводимое |
| **NFR-3** | Корректность подсчёта | завышение недопустимо; потеря < 0.01 % приемлема | выводимое из FR-4 |
| **NFR-4** | Анонимность | связь «голос ↔ человек» отсутствует в модели данных | явно |
| **NFR-5** | Отказоустойчивость | падение любого одного компонента не выводит систему из строя | наше |
| **NFR-6** | Масштабируемость | у каждого компонента есть путь роста; нет скрытых потолков | наше |
| **NFR-7** | Наблюдаемость | метрики, логи, трейсы, ошибки в едином окне | наше |
| **NFR-8** | Поддерживаемость | однонаправленные зависимости, единообразие, проверяемое линтером | наше |
| **NFR-9** | Безопасность | OWASP-базис, секреты вне кода, аудит админских действий | наше |

### NFR-2: что значит «доступность»

Ключевая метрика не uptime за месяц, а **доля успешно принятых голосов в окне
конкретного эфира**. Девять девяток за год не помогут, если минута ролика попала
в оставшуюся часть.

### NFR-3: асимметрия

```
потеряли 300 голосов из 30 млн   → 0.001 %, статистический шум
посчитали 300 лишних             → накрутка, репутационный ущерб
```

Поэтому: at-most-once там, где нельзя гарантировать exactly-once, и идемпотентность
там, где возможен ретрай.

## 5. Допущения

ТЗ не задаёт эти параметры. Фиксируем явно, чтобы ревьюер видел границу между
данным и придуманным.

| ID | Допущение | Значение | Если неверно |
|---|---|---|---|
| **A-1** | Конверсия зрителей в голоса | 30 % | архитектура линейна: меняется только число нод |
| **A-2** | Форма нагрузки внутри окна | 50 % в первые 15 с | меняется пиковый RPS, не дизайн |
| **A-3** | Одновременно активных опросов | 1, модель поддерживает N | ёмкость планируется по сумме |
| **A-4** | Вариантов в вопросе | до 10 | больше — растёт размер хэша, не более |
| **A-5** | Публичный показ результатов во время эфира | выключен по умолчанию | флаг в опросе |
| **A-6** | Регион | один | мультирегион — это L1/edge, отдельная работа |
| **A-8** | **Результаты нужны eventually, не в реальном времени** | дренаж ~5 мин | сжатие дренажа линейно дорожает по Redis, архитектура не меняется |
| **A-9** | Ожидаемая аудитория задаётся пер-опрос | поле `expected_audience` | ёмкость выводится функцией, а не константой |
| **A-7** | Срок хранения результатов | бессрочно | не влияет на дизайн |

**A-8 — самое ценное допущение.** ТЗ говорит «посмотреть результаты опроса (админка)» и не задаёт времени. Отсюда следует, что в окне эфира жёстко требуется только приём голосов, а дедуп и подсчёт отложимы — именно это позволило поставить Kafka впереди и уменьшить Redis вчетверо.

**A-1 — главное числовое допущение.** 100 млн зрителей ≠ 100 млн голосов, а конверсии в ТЗ нет. Теперь оно живёт в поле опроса, а не в константе.
Взято 30 % при типичных для ТВ долях процента: архитектура масштабируется линейно,
поэтому ошибка в допущении меняет счёт нод, а не решения.

## 6. Вне скоупа

| Что | Почему |
|---|---|
| Защита от технически подкованных, антифрод | ТЗ явно ограничивает: «не слишком защищённая от обхода» |
| Регистрация, профили, история голосований | противоречит «не требуют регистрации» и анонимности |
| Несколько вопросов в одном опросе | ТЗ: «1 вопрос» |
| Свободный текст в ответах | нет агрегата, нет обезличивания, нет дедупа по содержанию |
| Аудит-трейл отдельных голосов | противоречит анонимности; следствие — пересчёт через неделю невозможен, исключение во время дренажа доступно |
| **Fingerprinting в любом виде** | энтропии не хватает: при 30 млн голосующих ~18 бит дают потерю 99 %, а отказы смещены по модели устройства, то есть по демографии |
| **Повторное голосование из другого браузера на том же устройстве** | отпечаток различает браузеры, а не устройства; кросс-браузерный опирается на аппаратные сигналы, у которых энтропии ещё меньше. Закрывается только Turnstile-классом решений |
| Real-time результаты на студийном экране | не заявлено; потребовало бы SSE и другого профиля чтения |
| Мультирегиональность | не заявлена |
| k8s-манифесты | стенд на docker-compose; непроверенный YAML хуже, чем его отсутствие |

## 7. Трассировка: требование → проверка

Каждое требование проверяется автоматически, а не глазами.

| Требование | Как проверяется |
|---|---|
| FR-1, FR-1.1, FR-1.2 | unit: валидация голоса по типу и `min/max_choices` |
| FR-2 | smoke: создание опроса → `GET /p/{slug}` отдаёт 200, QR генерируется |
| FR-3 | smoke: голос без токена → 401; с токеном → 200 `counted` |
| FR-4 | smoke шаг 4: тот же токен на **другом инстансе** → `already_counted` |
| FR-5 | smoke: `/results` возвращает агрегат; unit: проценты от `ballots_total` |
| FR-6 | unit: FSM статусов, запрещённые переходы |
| FR-7 | integration: админский эндпоинт без JWT → 401 |
| FR-8 | smoke шаг 6: голос после `closes_at` → 409 |
| NFR-1 | k6: стоимость одного голоса → линейная экстраполяция ёмкости |
| NFR-2 | chaos: отказ каждого компонента, приём голосов продолжается |
| NFR-3 | k6: **сумма счётчиков = число успешных ответов**; unit: конкурентный дедуп |
| NFR-4 | ревью модели данных: в схеме нет поля, связывающего голос с человеком |
| NFR-5 | `make chaos-*`, каждый сценарий проверяет корректность агрегата |
| NFR-6 | нагрузочный профиль на 1 и 2 инстансах — линейность |
| NFR-7 | `make demo` поднимает Grafana с готовыми дашбордами |
| NFR-8 | CI: `golangci-lint` + `depguard` на границы слоёв |
| NFR-9 | CI: `gosec`, `govulncheck` |
| DR-1 | `make demo` на чистой машине |
| DR-3 | `docs/ai/` в репозитории |

Строка **NFR-4** — единственная, проверяемая ревью, а не тестом: отсутствие
возможности нельзя доказать тестом, можно только показать в схеме.
